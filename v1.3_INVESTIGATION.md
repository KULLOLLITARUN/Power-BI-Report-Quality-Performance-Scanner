## 1. Problem Statement & Root Cause Analysis

### 1.1 Observed Finding in Audit Entry 02
In `03 Xmas Sales`, 5 valid active measures were flagged as unused (`DAX_UNUSED_MEASURE`) by `pbiscan v1.2.0`:
- `Profit 20`
- `Delta Profit 21 20`
- `Delta Sales 21 18`
- `Delta Unit Sold 21 20`
- `Unit Sold 20`

### 1.2 Root Cause
Prior to v1.3, report visual extraction only inspected explicit top-level query structures:
- `prototypeQuery.Select`
- `prototypeQuery.OrderBy`
- `dataRoles` bindings
- Visual-level and page-level filter payloads

However, modern Power BI Desktop features (New Card visual reference labels, detail values, dynamic visual titles/subtitles, conditional formatting rules, dynamic axis bounds, visual header tooltips) store measure bindings inside the visual's **`objects`** block:

```json
"objects": {
  "referenceLabel": [
    {
      "properties": {
        "value": {
          "expr": {
            "Measure": {
              "Expression": { "SourceRef": { "Entity": "Sales" } },
              "Property": "Profit 20"
            }
          }
        }
      }
    }
  ],
  "referenceLabelDetail": [
    {
      "properties": {
        "detailValue": {
          "expr": {
            "Measure": {
              "Expression": { "SourceRef": { "Entity": "Sales" } },
              "Property": "Delta Profit 21 20"
            }
          }
        }
      }
    }
  ]
}
```

Because visual property subtrees were not traversed recursively, these measures were missed during extraction, leading to false-positive `DAX_UNUSED_MEASURE` findings.

## 2. Comprehensive PBIR Measure Reference Extraction Contract (v1.3)

In v1.3, the extraction engine recursively harvests measure references across all visual, page, report, and bookmark AST surfaces:

| Surface Category | JSON Path Pattern in `visual.json` / `page.json` | Power BI Feature |
|---|---|---|
| **1. Visual Data Query** | `prototypeQuery.Select[].Measure.Property` | Standard Charts, Bar, Line, Table, Matrix |
| **2. Sorting Directives** | `prototypeQuery.OrderBy[].Expression.Measure.Property` | Visual Sort By Measure |
| **3. Filter Payloads** | `filters[].expression.Measure.Property` | Visual-Level & Page-Level Filters |
| **4. Reference Labels** | `objects.referenceLabel[].properties.value.expr.Measure.Property` | New Card Visual Reference Metric |
| **5. Reference Label Details** | `objects.referenceLabelDetail[].properties.detailValue.expr.Measure.Property` | New Card Visual Delta / Target Variance |
| **6. Dynamic Titles** | `objects.title[].properties.text.expr.Measure.Property` | Dynamic / DAX Visual Titles |
| **7. Dynamic Subtitles** | `objects.subTitle[].properties.text.expr.Measure.Property` | Dynamic Visual Subtitles |
| **8. Conditional Formatting** | `objects.*[].properties.*.solid.color.expr.Measure.Property` | Data-Driven Fill & Font Color Formatting |
| **9. Visual Header Tooltips** | `visualContainerObjects.visualHeaderTooltip[].properties.text.expr.Measure.Property` | Header Info Expressions |
| **10. Bookmarks & Page AST** | `bookmarks[].explorationState...Measure.Property` | Bookmark Visual Overrides & States |

## 3. Shipped Architecture & Implementation

### 3.1 Recursive AST Expression Harvester
Rather than maintaining fragile path enumeration lists, the engine implements recursive AST tree walkers across the entire raw visual/page document:

- **Python**: `extract_measure_names` in `pbiscan/extraction/raw.py` (called from `parse_pbir_visual`, `parse_pbir_pages`, `report_parser.py`).
- **TypeScript**: `extractMeasureNamesFromExprTree` in `studio-ui/src/engine/semanticReferences.ts` (called from `clientScanner.ts`).

### 3.2 Threat Model & Design Decisions

1. **Safe Over-Matching vs. Destructive Under-Matching**:
   - `DAX_UNUSED_MEASURE` findings directly inform automated remediation plans in `pbiscan fix`.
   - **Under-matching** falsely marks an active measure as unused, leading to deletion and broken visuals.
   - **Over-matching** leaves a measure in the model without deletion.
   - Therefore, recursive harvesting intentionally errs on the side of safety.
2. **Name-Only Matching**:
   - The harvester matches by measure name (`Measure.Property`) and does not strictly require `SourceRef.Entity` resolution.
   - While a visual referencing `Sales[Profit]` also protects an identically named `Budget[Profit]`, this is an intentional safety hedge protecting valid measures across multi-table models.
3. **Non-Measure String Isolation**:
   - Plain string literals (e.g. static title strings, `displayName`, `queryRef` text) lack a `Measure` AST object and are strictly ignored.
   - Verified by unit tests in both Python (`test_non_measure_string_literals_are_not_extracted`) and TypeScript (`ignores non-string Property types and non-measure string literals`).
4. **Type Enforcement Parity**:
   - Python: requires `isinstance(prop, str) and prop` within an `isinstance(obj["Measure"], dict)`.
   - TypeScript: requires `typeof prop === 'string' && prop.length > 0` within `typeof obj.Measure === 'object' && !Array.isArray(obj.Measure)`.
   - Non-string properties (numbers, objects, booleans, arrays) and empty strings are rejected identically. Whitespace strings (e.g. `'   '`) are preserved as-is without trimming in both engines so exact-match reachability behaves identically.
5. **Stringified JSON Handling**:
   - Legacy Power BI report layouts store visual `config` and `filters` as escaped JSON strings inside JSON fields.
   - Both Python (`decode_json_field`) and TypeScript (`decodeJsonField`) decode these embedded strings before recursive harvesting.

## 4. Golden Test Fixture & Verification

The contract is validated by:

1. **Golden Fixture (`tests/golden/test_pbir_objects_references`)**:
   - Contains a New Card visual binding `TotalSales` in projections, `CardRefMetric` in `referenceLabel`, `CardDetailMetric` in `referenceLabelDetail`, and other properties for titles, subtitles, conditional color formatting, and axis bounds.
   - Contains exactly one true-positive control measure: `GenuinelyUnusedMetric`.
2. **Contract Test (`tests/golden/test_pbir_objects_fixtures.py`)**:
   - Asserts all 7 objects-bound active measures are extracted in visual references.
   - Asserts `DAX_UNUSED_MEASURE` produces exactly 1 finding (`Measure: GenuinelyUnusedMetric`).
   - Asserts plain string literals matching measure names do not prevent unused detection, validated alongside true-positive sibling controls.
3. **Engine Parity Tests (`tests/unit/test_client_scanner_parity.py`)**:
   - Automatically runs `test_pbir_objects_references` through both Python and TypeScript client engines, ensuring identical finding counts, scores, and metadata.
   - Runs cross-engine AST edge-payload contract test (`test_ast_measure_extraction_edge_payload_parity`) asserting identical extraction on numbers, booleans, arrays, nulls, whitespace, and non-measure string literals.
