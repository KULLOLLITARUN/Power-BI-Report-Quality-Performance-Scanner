## 1. Problem Statement & Root Cause Analysis

### 1.1 Observed Finding in Audit Entry 02
In `03 Xmas Sales`, 5 valid active measures were flagged as unused (`DAX_UNUSED_MEASURE`) by `pbiscan v1.2.0`:
- `Profit 20`
- `Delta Profit 21 20`
- `Delta Sales 21 18`
- `Delta Unit Sold 21 20`
- `Unit Sold 20`

### 1.2 Root Cause
`PBIPReader._extract_pbir_visual()` accurately extracts measure identifiers from:
- `prototypeQuery.Select`
- `prototypeQuery.OrderBy`
- `dataRoles` bindings
- Visual-level and page-level filter payloads

However, modern Power BI Desktop (New Card visual, Multi-Row Cards, Dynamic Visual Titles, Conditional Formatting, and Subtitles) stores measure bindings inside the visual's **`objects`** block:

```json
"objects": {
  "referenceLabel": [
    {
      "properties": {
        "value": {
          "expr": {
            "Measure": {
              "Expression": { "SourceRef": { "Entity": "Measure" } },
              "Property": "Profit 20"
            }
          }
        }
      }
    }
  ],
  "referenceLabelDetail": [
    {
      "properties": {
        "detailValue": {
          "expr": {
            "Measure": {
              "Expression": { "SourceRef": { "Entity": "Measure" } },
              "Property": "Delta Profit 21 20"
            }
          }
        }
      }
    }
  ]
}
```

Because `PBIPReader` did not inspect `objects`, these measures were missed during extraction, leading to false-positive unused measure findings in `D004`.

## 2. Comprehensive PBIR Measure Reference Extraction Contract (v1.3)

In v1.3, `PBIPReader` must extract measure references from all of the following PBIR AST surfaces:

| Surface Category | JSON Path Pattern in `visual.json` | Example Power BI Feature |
|---|---|---|
| **1. Visual Data Query** | `prototypeQuery.Select[].Measure.Property` | Standard Charts, Bar, Line, Table, Matrix |
| **2. Sorting Directives** | `prototypeQuery.OrderBy[].Expression.Measure.Property` | Visual Sort By Measure |
| **3. Filter Payloads** | `filters[].expression.Measure.Property` | Visual-Level & Page-Level Filters |
| **4. Reference Labels** | `objects.referenceLabel[].properties.value.expr.Measure.Property` | New Card Visual Reference Metric |
| **5. Reference Label Details** | `objects.referenceLabelDetail[].properties.detailValue.expr.Measure.Property` | New Card Visual Delta / Target Variance |
| **6. Dynamic Titles** | `objects.title[].properties.text.expr.Measure.Property` | Dynamic / DAX Visual Titles |
| **7. Dynamic Subtitles** | `objects.subTitle[].properties.text.expr.Measure.Property` | Dynamic Visual Subtitles |
| **8. Conditional Formatting** | `objects.*[].properties.*.solid.color.expr.Measure.Property` | Data-Driven Fill & Font Color Formatting |
| **9. Visual Header Tooltips** | `visualContainerObjects.visualHeaderTooltip[].properties.text.expr.Measure.Property` | Header Info Expressions |

## 3. Implementation Plan for v1.3

### 3.1 Architecture: Recursive Object Expression Harvester
Instead of ad-hoc path parsing, implement a general-purpose recursive Expression AST harvester in `PBIPReader`:

```python
def _extract_measure_names_from_expr_tree(obj: Any) -> set[str]:
    """Recursively traverses any JSON/dict subtree and extracts all Measure.Property names."""
    refs = set()
    if isinstance(obj, dict):
        if "Measure" in obj and isinstance(obj["Measure"], dict) and "Property" in obj["Measure"]:
            refs.add(obj["Measure"]["Property"])
        for v in obj.values():
            refs.update(_extract_measure_names_from_expr_tree(v))
    elif isinstance(obj, list):
        for item in obj:
            refs.update(_extract_measure_names_from_expr_tree(item))
    return refs
```

This ensures full future-proof coverage across all current and future visual property expressions in PBIR without fragile path enumeration.
